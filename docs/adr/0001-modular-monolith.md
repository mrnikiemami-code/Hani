# ADR-0001 — Modular Monolith + Clean Architecture

- **وضعیت:** Accepted
- **تاریخ:** 2026-11-10
- **تصمیم‌گیرندگان:** تیم معماری TravelCore

## زمینه

TravelCore باید هم سریع به بازار برسد و هم بدون بازنویسی دامنه به میکروسرویس تبدیل شود. تیم اولیه کوچک است و تراکنش‌های رزرو/پرداخت/تسویه نیاز به consistency دارند.

## تصمیم

- یک **مونولیت ماژولار** با مرزهای دامنه‌ای صریح.
- هر ماژول چهار پروژه: `Domain`, `Application`, `Infrastructure`, `Presentation`.
- هر ماژول `DbContext` و Schema مستقل.
- ارتباط بین ماژول‌ها فقط از طریق `TravelCore.Contracts.*` و Integration Event.
- API Host فقط Composition Root است.

## پیامدها

**مثبت:** سرعت تحویل، تراکنش ساده، هزینه عملیاتی کم، مسیر مشخص استخراج.

**منفی:** نیاز به انضباط معماری، خطر تبدیل شدن به «مونولیت به‌هم‌ریخته» در صورت نقض قواعد.

## الزامات

- ArchitectureTests در CI.
- بازبینی PR بر اساس قواعد `CONTRIBUTING.md`.
- هیچ Join بین Schemaها.

## جایگزین‌های رد شده

- میکروسرویس از روز اول: پیچیدگی DevOps و تراکنش توزیع‌شده برای تیم کوچک.
- مونولیت لایه‌ای سنتی: مرز ماژول ندارد و استخراج سخت است.
